# Архитектура

## Слои

```
core/    операции, геометрия, породы, валидатор     ← без I/O, без UI
  ↓
calc/    раскрой, материалы, отходы, себестоимость
  ↓
render/  SVG (2D), trimesh → .glb (3D)
  ↓
io/      проект (JSON), PDF (WeasyPrint)
  ↓
web/ cli/  оболочки
```

Зависимости только сверху вниз. `core/` не знает о существовании остальных.

## Ключевые решения и их причины

**Геометрия на `shapely`, а не на сетке.**
Угловые резы дают параллелограммы и обрезки. Одно универсальное представление
(полигон + порода) закрывает и шахматку, и кубы, и ёлочку. Цена — производительность,
лечится кэшированием.

**Кэш по хешу программы.**
Результат каждой операции кэшируется по хешу префикса программы. Правка последней
операции не пересчитывает всё. Ключ — стабильная сериализация операций.

**Собственный SVG-writer.**
Один вектор идёт в браузер, в PDF и на печать 1:1. Никаких растровых
рассинхронов между экраном и цехом.

**3D без JS.**
`trimesh` собирает меш из полигонов ядра с фаской и экспортирует `.glb`.
Браузер показывает через `<model-viewer>`. Мы не пишем и не отлаживаем three.js.

**HTMX вместо SPA.**
Весь интерфейс — Python + шаблоны. Обмен — фрагменты HTML. Локально round-trip
незаметен. Перерисовывать надо частично: отдельные фрагменты, не всю страницу.

**Проект — программа, а не снимок.**
JSON со списком операций и `schema_version`. Читаемый, диффабельный,
воспроизводимый. Миграции схемы — отдельный модуль с версии 2.

## Чертежи для мастерской

Отдельный режим рендера: чёрно-белый, каждая деталь подписана буквой породы,
проставлены размеры и номера шагов. Печатается на офисном лазернике.
Цветной рендер — для превью, ч/б — для работы.

## Производительность

- Живое редактирование должно укладываться в ~100 мс на перерисовку.
- Тяжёлые вещи (оптимизация раскроя, эволюционные генераторы) — в отдельном
  потоке/процессе, с прогрессом в UI.
- Бенчмарк в тестах: доска 20×30 ячеек, 3 склейки — фиксируем верхнюю границу.

## Оптимизация раскроя

Одномерная задача раскроя (реек из досок стандартной длины):
first-fit-decreasing как база + локальный поиск с ограничением по времени.
Не гонимся за оптимумом, гонимся за предсказуемостью и объяснимостью:
пользователь должен видеть, почему нужно именно столько материала.

## Генераторы узоров

Работают **над пространством программ**, а не над пикселями. Мутируют состав
щита, углы резов, сдвиги и отражения. Любой результат изготовим по построению.
Фитнес-функция для эволюционного режима: контраст, ритм, симметрия,
экономичность, реализуемость.
