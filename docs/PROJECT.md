# Карта проекта: BoardForge

## Что это
Генератор узоров для торцевых разделочных досок — не рисовалка, а инструмент, по результату которого столяр реально изготавливает доску: узор, раскрой, расчёт материала, пошаговая инструкция.

Ключевая идея, из которой следует всё остальное: **доска — это программа столярных операций, а не картинка**. Проект хранится как последовательность `Glue → Crosscut → StandOnEnd → Cut → Assemble → Crop`, а узор, карта раскроя, расход и инструкция **выводятся** из неё. Отсюда главное отличие от аналогов: сгенерировать неизготовимый узор физически невозможно, а валидатор объясняет словами, почему нарисованное не собирается.

Проект недельный, вайбкодинг-спринт. Критерии оценки: можно ли изготовить настоящую доску, разберётся ли человек, не писавший код, насколько разнообразны узоры, насколько всё стабильно.

**Статус: закрыты дни 1–6 из 7, день 7 в работе.** Ядро, геометрия, породы, рендер с текстурой торца, веб-оболочка, углы, генераторы, цех, впечатление. По дню 7: закрыта кодировка консоли (CLI падал в Git Bash и возвращал 1 в `workshop`), набор тестов разделён на быстрый и полный (около трёх минут против двадцати с лишним), появились README с честными границами и комплект демо-проектов. CLI-демон на `rich` снят с дня осознанно.

## Стек
Python-first. Ядро без единой UI-зависимости, оболочки поверх. Осознанно: солверы и расчёты пишутся и тестируются на Python комфортнее всего, а весь интерфейс — тоже Python, браузер только показывает готовый SVG.

- **Язык:** Python ≥3.13 (окружение на CPython 3.13.7), `uv` для зависимостей
- **Геометрия:** `shapely` 2.1.2, `numpy` 2.5.2 — рез это пересечение полигонов, пересборка это аффинные преобразования
- **Породы:** `pyyaml` 6.0.3, данные в `species.yaml`
- **2D-рендер:** собственный SVG-writer без библиотек — один вектор идёт и в браузер, и в печать
- **Web:** FastAPI + Jinja2 + HTMX, обмен фрагментами через `hx-swap-oob`
- **CLI:** `argparse` (не Typer — см. Р17)
- **Тесты:** `pytest`, `hypothesis` для property-тестов; `ruff` (line-length 90, E/F/I/UP/B/SIM)
- **Сборка:** hatchling, src-layout
- **Формат проекта:** JSON программы операций + `schema_version`
- **Локально:** Windows, PowerShell, `C:\dev\boardforge`
- **Git:** `papsuevgeorgiy-ux/boardforge`, приватный, HTTPS (`gh auth setup-git`), теги `day1`…`day6`
- **3D:** `trimesh` 5.0 → `.glb`, показ через `<model-viewer>` 4.1. Просмотрщик лежит локально в `web/static/` (979 КБ) рядом с htmx: «работает без сети» — заявленное свойство, и ради 3D его не отменяем
- **PDF:** WeasyPrint 69.0 поверх системного GTK (MSYS2, Pango 15701). Импортируется только лениво, внутри функции
- **Триангуляция:** `shapely.constrained_delaunay_triangles` (GEOS 3.13) — новой зависимости 3D не потребовало
- **`rich` не добавлен.** Интерактивный демон снят с дня 7: новая зависимость на последнем дне поехала бы в тот же `uv sync`, который в этот день проверяется на чистой машине, а видит демона со стороны никто. Р17 оставлял его вопросом, а не обязательством

## Ключевые модули и точки входа
| Модуль | Где | За что отвечает |
|--------|-----|-----------------|
| DSL операций | `core/ops.py` | Единственный источник истины о доске. Всё остальное — производные. Проверка аргументов в конструкторе, сериализация в словарь |
| Смена проекции | `StandOnEnd` в `core/geometry.py` | Ключевая операция: до неё видна пласть щита, после — план доски. Переставляет измерения, встречается не более раза **на заготовку** (Р9: щитов может быть несколько, и торцуют их в разное время). Реализована как масштаб по X — корректно только при инварианте «сразу после торцовки», защищено проверкой в самой геометрии |
| Происхождение ячейки | `Origin` в `core/piece.py` | Щит, номер рейки, смещение по длине рейки, порода. Переживает склейки, развороты и обрезку. Без него текстура рассыпается на пёстрый шум |
| Ориентация | `Orientation` в `core/piece.py` | Поворот в плане + отражение поперёк оси. Копится на резах и склейках, `StandOnEnd` обнуляет. Благодаря ей `reversed` виден в текстуре, а не только в геометрии |
| Отражение детали | `flipped` в `geometry.assemble` | Р21: настоящее зеркало полигона поперёк продольной оси, а не только разворот текстуры. На прямоугольной ячейке тождественно (потому обратно совместимо), на наклонной меняет наклон — единственный способ получить встречный наклон из одного щита. `reversed` не годится: поворот на 180° наклон сохраняет |
| Валидатор | `validate()` в `core/program.py` | Возвращает **разбор** (`Issue` с уровнем и номером операции), а не «да/нет». Это главная функция инструмента — она же выведена первой в правой колонке веба. Кроме последовательности операций проверяет **состав щита**: `_BilletState` тянет через заготовки происхождение по `Glue` и угол последнего реза, и при зеркальной склейке под углом требует, чтобы породный цикл повторялся (иначе часть швов остаётся без материала). Проверка статическая: такая программа исполнима, дыры видны только глазом |
| Мульти-щит | `Glue(id=…)`, `Assemble(pieces=[(billet, i)])` | Состояние программы — именованный набор заготовок. Без этого нельзя сказать «ряд N не выводится из щита А, нужен щит Б» (Р9) |
| Угловые узоры | `core/patterns.py` | Параметрические генераторы (`StripedPanel`, `chevron`, `herringbone`): считают углы и сдвиги из геометрии и **выписывают программу**. Сдвиг зеркальной полосы накапливается по всем полосам, а не чередуется, и берётся по модулю периода узора — вывод в Р22 |
| Результат реза | `SliceResult` в `core/geometry.py` | Полосы, недорез по длине и **измеренная** площадь отхода. При угловом резе отход клиновидный, и из недореза не выводится. `placements_mm` помнит, где полоса лежала до нормализации — без этого генераторы не соберут узор обратно. Дальше площадь едет в `CutYield.waste_mm2`: на дне 5 без неё смета молча потеряет клинья |
| Порода в точке | `Part.species_at` | Через ленивый `STRtree` в поле `Part._index` (на равенство не влияет). Линейный перебор ячеек превращал координатную проверку швов в 80 секунд, с индексом 1.2. Нужна и тестам, и подсказкам в UI |
| Обратный ход припусков | `calc/allowances.py` | Все размеры в программе чистовые (Р0.1). Пропил, строгание и обрезка живут только здесь. Смена диска меняет смету, но не рисунок |
| Подбор габарита | `core/fitting.py` | Итеративный: собрать, померить, поправить. Аналитическая формула промахивалась на десятки мм — обрезка и остаток от торцовки в неё не входят. Показывает достижимый размер и отклонение, а не молча подгоняет |
| Два слоя рендера | `render_structure` / `render_texture` | Структура 107 мс, текстура 334 мс на 600 ячейках — замер Дня 6 через `tools/bench.py`, условия и оговорки в known issues (числа Дня 5 — 127 и 433 — там же, разница внутри шума). Размеры 60 КБ и 749 КБ — с Дня 2, не перемерялись. Контракт проверен тестом побайтово: структура + текстура = полный документ. Разойдись они — превью перестанет совпадать с печатью |
| Текстура торца | `render/texture.py` | Сид из `Origin.strip_key` через `blake2b` (не встроенный `hash` — он солится при старте). Дуги с центром вне ячейки, увод сердцевины абсолютный в мм: ствол вдоль себя не расширяется |
| Кубы | `core/cubes.py` | Мозаика падающих блоков. **Два щита-близнеца**, набранные одним циклом со сдвигом на рейку: из одного не строится ни при каких сдвигах (Р23, вывод в заголовке модуля). Годные полосы выбираются измерением — длина не меньше 0.9 от наибольшей и контур цельный |
| Правило сдвигов | `core/lattice.py` | Отвечает на вопрос Р22 «когда сдвиг сведёт узор» арифметикой. `Lattice` — про решётку узора, `LineFamily` — про то, чтобы конкретные линии остались сквозными. `common_quantum` согласует два условия (у кубов их два). Отказ — `NoLatticeSolution` словами, а не ближайшее приближение |
| Библиотека узоров | `core/library.py` | 14 параметрических шаблонов. Одиннадцать ортогональных строятся одним `assemble_columns`: разница между шахматкой, кирпичом и плетёнкой — только таблица сдвигов и номер щита. Каждый объявляет период трансляции — это и есть его тест на схождение |
| Оценка узора | `core/fitness.py` | Пять мер, все по сетке проб, а не по ячейкам. Экономичность считается тем же обратным ходом припусков, что и смета: шахматка 0.72, шеврон 0.30, кубы 0.053. Реализуемость считает **роды** замечаний, а не их число — иначе задуманная волосяная линия топит кубы сорока одинаковыми жалобами |
| Генератор | `core/generate.py` | Генерируется `Genome` (шаблон + параметры), программа выводится. Сид детерминирован: породы берутся из отсортированного справочника. Результат прогоняется через валидатор и `safety.inspect`, негодный геном выбрасывается |
| Импорт картинки | `core/imaging.py` | Квантование в CIELAB плюс **подгон под ограничение рядов**: столбец доски — срез щита, поэтому столбцы кластеризуются по немногим щитам. Точность сообщается честно, щитов может выйти меньше заказанного |
| Карта раскроя | `calc/cutlist.py` | Рейки закупки (`A1`) и полосы (`A-01`) — разные вещи и разные таблицы. Перечисляет **все** стадии реза: у углового узора их три, и без номеров вторую пачку от первой не отличить. `reusable` отделяет годный остаток от клиньев измерением: цельная полоса площадью не меньше худшей из пошедших в дело |
| Себестоимость | `calc/estimate.py` | По объёму **закупки**, а не доски: у кубов разница в двадцать раз. Цены — параметр, а не свойство доски, и в проект не пишутся. Вес считается по породе каждой ячейки: клён с венге и клён с орехом различаются на четверть |
| Раскрой по длине | `calc/nesting.py` | FFD плюс возмущённый порядок с бюджетом по времени. Возмущение обязано ломать сам порядок убывания — простая перестановка тут же пересортировывается и не меняет ничего. Ширина рейки не моделируется: план — нижняя оценка метража |
| Предупреждения о породах | `calc/warnings.py` | Не изготовимость: та же программа с любым справочником даёт ту же геометрию. В оценку узора не входят — иначе генератор избегал бы вишни с грабом так же, как неизготовимого клина. Порог 3.0 п.п. с якорем «клён с орехом не ругается» |
| Чертёж | `render/blueprint.py` + `BLUEPRINT` в `STYLES` | Режим — запись в `STYLES`, в `svg.py` из-за него появилось одно поле `label`, устроенное как давнее `background`. Белая заливка, а не серая: серое растрируется лазерником и съедает буквы поверх себя |
| Временный каталог тестов | `conftest.py` в корне | `--basetemp` в связке с Python 3.13 делал каталог недоступным навсегда после одного прогона под другим токеном. Каталоги с постоянными именами создаются обычным `mkdir` и наследуют права репозитория; режим `0o700` остаётся только у нумерованных листьев, которые не переиспользуются. Полный разбор — в заголовке файла |
| Распечатка | `io/report.py` | Собирает готовое из `calc/` в одну HTML-страницу. Арифметики в ней нет намеренно: начни она считать сама — разойдётся с интерфейсом молча. Та же разметка уходит в PDF — не пересобираясь второй раз |
| Принтер | `io/pdf.py` | WeasyPrint импортируется **внутри функции**: без системного GTK его импорт падает `OSError`, и наверху модуля он утянул бы за собой весь `boardforge`, включая `serve` и `swatches`. Отказ — фраза с командой установки, не трейсбек. Проверяется отдельным процессом в тесте |
| Шаги инструкции | `io/steps.py` + `Program.trace()` | Шаг — операция, картинка шага — состояние верстака после неё. Кадры берутся из того же прохода, что и `run()` (общий `_advance`), а не исполнением префиксов: большинство префиксов валидатор законно не пропускает (Р28). Числа в шаге измерены по кадру. Здесь же `describe` — переехала из `web/presenters.py`, чтобы панель и распечатка говорили одними словами |
| 3D | `render/mesh.py` | Ячейка → призма, порода → цвет вершин. Фаска без булевых операций: крайняя ячейка режется линией фаски, и каждая часть становится своей призмой (Р29). Проверка числом — объём без фаски точно равен площади ячеек на высоту. Экспорт в метрах и с поворотом Z-up → Y-up: `trimesh` оси не меняет |
| История правок | `past` / `future` в `web/state.py` | Хранит программы целиком: обратной операции к «подобрать габарит» не существует, подбор переписывает сразу несколько операций. Все правки идут через единственную дверь `set_program` — прошедшая мимо откатывалась бы не туда |
| Маршруты веба | `web/__init__.py` | Страница `/`, фрагменты `/fragment/board` и `/fragment/model`, правки `/strips`, `/size`, `/generate`, `/units`, `/history`, проект `/project/save`, `/project/open`, `/project.json`, цех `/workshop`, `/workshop.pdf`, `/blueprint.svg`, `/board.glb`. ## Как запустить / проверить
```powershell
cd C:\dev\boardforge
uv sync
uv run pytest -m "not slow"  # быстрый набор, ~3 мин — им гоняют в разработке
uv run pytest                # полный, ~14 мин — им определяется зелёное
uv run ruff check .
```

Демо-проекты из комплекта открываются и правятся как любой другой проект:
```powershell
uv run boardforge serve --project projects/01-checkerboard-classic.json
uv run boardforge workshop --project projects/05-chevron-oak.json --pdf
```

Веб-интерфейс — основной способ проверить, что цепочка цела:
```powershell
uv run boardforge serve      # поднимает FastAPI и открывает браузер
```
Собрать доску, поправить состав щита, задать габарит, сохранить проект. Если валидатор показывает разбор программы словами — цепочка операции → геометрия → рендер → веб цела целиком.

Визуальная проверка (единственный способ поймать часть дефектов — тесты их не видят):
```powershell
uv run boardforge swatches                    # лист пород
uv run boardforge examples --scale 5          # демо-доски (--diagnostics для стендов)
uv run boardforge contact-sheet               # всё разом одной страницей
start chrome "$PWD\out\contact-sheet.svg"
```

Распечатка в мастерскую — итог дней 5–6:
```powershell
uv run boardforge workshop --template chevron --pdf
start chrome "$PWD\out\workshop\workshop.html"
```
Кладёт `out/workshop/`: `workshop.html`, `blueprint.svg` и `workshop.pdf`.
В интерфейсе то же самое: панель «Цех» справа, кнопки «Распечатка», «PDF»
и «Чертёж»; панель «В объёме» показывает доску в 3D — просмотрщик грузится
не раньше, чем его попросят.

Проверить принтер отдельно:
```powershell
uv run python -m weasyprint --info
```
Ответ версией — GTK на месте. `OSError` про `libgobject-2.0-0` — нужен MSYS2
и `pacman -S mingw-w64-x86_64-pango`; всё остальное в приложении при этом
работает, ляжет только PDF.

Замер производительности — одним и тем же кодом, чтобы дни сравнивались:
```powershell
$env:PYTHONPATH = "."; uv run python tools\bench.py
```

**Windows-специфика:** `.svg` не имеет программы по умолчанию — открывать через `start chrome "$PWD\путь"` или перетаскиванием в браузер. Все команды только из корня проекта. Не править YAML в Notepad — ломает и структуру, и UTF-8; только VS Code.

## Чего в проекте нет и почему

Раздел заменил два прежних — «бэклог» и «намеренно не сделано». На седьмом дне

одно и то же — чего в проекте нет. Причина у каждой строки.

1. **Интерактивный CLI-демон на `rich`.** Нет: новая зависимость на последнем
   дне поехала бы в тот самый `uv sync`, который в этот день проверяется на

3. **Обратная задача для угловых узоров.** Нет: полный солвер есть только для
   ортогональных случаев, для угловых даны параметрические генераторы

5. **Штриховка граней кубов в ч/б-чертеже.** Нет: в чёрно-белом грани не
   читаются. То, что принимали за них до дня 6, было артефактом объединения
   контуров — то есть пункт не «ухудшился», а впервые назван честно

   тест в последний день виден, а разница формулировок нет
